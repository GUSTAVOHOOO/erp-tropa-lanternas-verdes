# Propostas de revisão

## C1 — Revisão de atribuição

A action aceita dados tipados pelo cliente, não verifica papel/sessão, usa o objeto original após validar, usa a forma de erros do Zod 3 e captura o `redirect()` dentro do `try`. A menor correção é exigir Guardião antes da validação, receber `unknown`, usar `parsed.data` e separar falha de gravação da revalidação/navegação:

```ts
'use server'
import { redirect } from 'next/navigation'
import { revalidatePath } from 'next/cache'
import { z } from 'zod'
import { exigirPapel } from '@/lib/dal'
import { atribuicaoSchema } from '@/lib/schemas/ocorrencia'
import { atribuirResponsavel } from '@/lib/ocorrencias'
import type { ResultadoAcao } from '@/lib/resultado-acao'

export async function atribuir(dados: unknown): Promise<ResultadoAcao> {
  await exigirPapel('guardiao') // [AUTH-05]
  const parsed = atribuicaoSchema.safeParse(dados) // [FORM-17]
  if (!parsed.success) {
    return { ok: false, errors: z.flattenError(parsed.error).fieldErrors } // [FORM-18]
  }

  try {
    await atribuirResponsavel(parsed.data.id, parsed.data.responsavelId)
  } catch {
    return { ok: false, erro: 'Não foi possível atribuir.' }
  }

  revalidatePath('/painel/ocorrencias')
  redirect('/painel/ocorrencias') // [API-14] [ROTA-20]
}
```

A checagem do papel cobre autorização na própria Server Action, mesmo que o proxy já proteja `/painel`. O `redirect` fica fora do `try` para que a navegação após sucesso não seja confundida com erro da gravação. A proposta pressupõe que `exigirPapel('guardiao')` tenha a assinatura indicada no caso.

## C2 — Lista privada

```tsx
// app/(painel)/painel/ocorrencias/page.tsx
import { verificarSessao } from '@/lib/dal'
import { setorParaFiltro } from '@/lib/sessao'
import { listarOcorrencias } from '@/lib/ocorrencias'
import { EstadoVazio } from '@/components/estado-vazio'

type Props = {
  searchParams: Promise<{ setor?: string }>
}

export default async function Pagina({ searchParams }: Props) {
  const sessao = await verificarSessao() // [AUTH-04]
  const { setor } = await searchParams // [ROTA-10]
  const setorId = setorParaFiltro(sessao, setor) // [AUTH-07]
  const itens = await listarOcorrencias({ setorId })

  if (itens.length === 0) {
    return <EstadoVazio mensagem="Nenhuma ocorrência encontrada para este setor." /> // [API-09]
  }

  return (
    <ul>
      {itens.map((item) => <li key={item.id}>{item.titulo}</li>)}
    </ul>
  )
}
```

A decisão do setor ocorre no servidor a partir da sessão e do helper: o Guardião pode filtrar por qualquer setor; para Lanterna, o helper deve impor o setor da sessão, sem confiar na URL. A página privada verifica sessão mesmo com o proxy. `searchParams` é assíncrono no Next.js 16.4; a assinatura proposta o aguarda antes de usar. Caso o helper não valide/normalize a entrada da URL, valide-a antes de passá-la adiante, conforme ROTA-11; a bancada não fornece a assinatura nem o comportamento interno desse helper.

Estados a cobrir: carregamento com `loading.tsx` e skeleton; vazio com explicação e ação útil (por exemplo, limpar filtro, se aplicável); erro com `error.tsx`, mensagem humana e opção de tentar de novo; sucesso com a lista. O ramo vazio está ilustrado. A captura de erros da listagem deve ficar na fronteira de erro da rota, não transformar falha de serviço em lista vazia. [API-09]

## C3 — Justificativa acadêmica

Não dá para afirmar que o professor exige Axios, TanStack Query e cookie HMAC. Nenhum PDF está disponível nesta bancada; portanto não conferi os slides e não atribuo a eles uma exigência. O que se pode afirmar é que **a referência da skill registra** Axios como alternativa ensinada, mas a decisão local é usar `fetch` nativo (DEC-01); registra TanStack Query como tema de slide, mas a decisão do grupo é não usar cache de cliente (DEC-02); e fecha a lista de dependências, exigindo registrar uma nova decisão antes de adicionar bibliotecas (STACK-06). A referência consultada para esses três pontos mistura `[SLIDE]` e `[DECISÃO]`, que não são a mesma fonte. Não consultei uma regra sobre HMAC, então não concluo qual formato de cookie é requerido.

Eu orientaria o colega a não instalar Axios nem TanStack Query nem citar os três itens como exigência dos slides com a evidência atual. Deve seguir as decisões registradas para este projeto; se houver motivo para mudar dependências, propor e registrar explicitamente uma nova `[DECISÃO]`. Para afirmar o que os slides exigem ou decidir sobre HMAC, é preciso conferir o material pertinente quando estiver disponível. A política da skill reforça que, sem o PDF, devemos dizer “a referência da skill registra…”.

## C4 — Mudança pequena

Alteração apenas de classes responsivas, mantendo a aparência grande em telas maiores:

```tsx
export function Titulo() {
  return <h1 className="text-3xl font-bold text-foreground md:text-5xl">Central de Comando</h1> // [CSS-03]
}
```

A classe base reduz o título no celular e `md:text-5xl` preserva o tamanho a partir do breakpoint médio. Verificação adequada: inspecionar o título em viewport de 375 px e também em desktop para confirmar legibilidade e preservação do visual. Isto é uma proposta; não executei a aplicação nem testes.
