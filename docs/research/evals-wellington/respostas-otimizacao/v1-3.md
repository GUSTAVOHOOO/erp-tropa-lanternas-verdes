# Propostas

## C1 — Revisão de atribuição

A action recebe entrada do cliente, então o tipo TypeScript não substitui validação. Além disso, a autorização precisa ocorrer dentro da própria Server Action. O `redirect()` lança uma exceção de controle do Next.js; mantê-lo dentro do `try` faz o `catch` transformar navegação bem-sucedida em erro. A correção mínima é autorizar, validar `unknown`, usar os dados validados e deixar gravação/revalidação/redirecionamento fora do `try`:

```ts
'use server'
import * as z from 'zod'
import { redirect } from 'next/navigation'
import { revalidatePath } from 'next/cache'
import { exigirPapel } from '@/lib/dal'
import { atribuicaoSchema } from '@/lib/schemas/ocorrencia'
import { atribuirResponsavel } from '@/lib/ocorrencias'
import type { ResultadoAcao } from '@/lib/resultado-acao'

export async function atribuir(dados: unknown): Promise<ResultadoAcao> {
  await exigirPapel('guardiao') // [AUTH-05]

  const parsed = atribuicaoSchema.safeParse(dados) // [FORM-17]
  if (!parsed.success) {
    return { ok: false, errors: z.flattenError(parsed.error).fieldErrors } // [FORM-18]
  }

  try {
    await atribuirResponsavel(parsed.data.id, parsed.data.responsavelId)
  } catch {
    return { ok: false, erro: 'Não foi possível atribuir.' }
  }

  revalidatePath('/painel/ocorrencias')
  redirect('/painel/ocorrencias') // [ROTA-20]
}
```

O proxy não substitui a checagem da action. `exigirPapel` também verifica a sessão e impede Lanternas de atribuir. A navegação após sucesso fica preservada e não é engolida pelo `catch`. Fontes: AUTH-05 [DOCS + SLIDE], FORM-17/18 [SLIDE], ROTA-20 [SLIDE + DOCS], API-14 [SLIDE].

## C2 — Lista privada

`searchParams` é assíncrono no Next 16. A página deve verificar a sessão, calcular o filtro no servidor e chamar a camada de serviço disponível, sem aceitar diretamente um filtro que permita ao Lanterna consultar outro setor:

```tsx
// app/(painel)/painel/ocorrencias/page.tsx
import { verificarSessao } from '@/lib/dal'
import { setorParaFiltro } from '@/lib/sessao'
import { listarOcorrencias } from '@/lib/ocorrencias'
import { EstadoVazio } from '@/components/estado-vazio'
import { ListaOcorrencias } from '@/components/lista-ocorrencias'

type Props = {
  searchParams: Promise<{ setor?: string }>
}

export default async function Pagina({ searchParams }: Props) {
  const sessao = await verificarSessao() // [AUTH-04]
  const { setor } = await searchParams // [ROTA-10]
  const setorId = setorParaFiltro(sessao, setor) // [AUTH-07]
  const itens = await listarOcorrencias({ setorId })

  if (itens.length === 0) {
    return <EstadoVazio mensagem="Nenhuma ocorrência encontrada." /> // [API-09]
  }

  return <ListaOcorrencias itens={itens} />
}
```

`EstadoVazio` e `ListaOcorrencias` representam os componentes da interface; devem receber os tipos reais do projeto. O Guardião pode usar o setor vindo da URL (ou ver todos quando não há filtro); `setorParaFiltro` fixa o Lanterna ao setor da sessão. Cobrir os quatro estados: carregamento em `loading.tsx` (skeleton), vazio com explicação e ação útil, erro em `error.tsx` com mensagem humana e tentativa de novo, e sucesso com a lista. Se o serviço puder falhar, o estado de erro deve ser acionado pelo mecanismo da rota; não capturar a falha para renderizar uma lista vazia. Fontes: AUTH-04 [DOCS + SLIDE], AUTH-07 [DECISÃO + DOCS], ROTA-10 [SLIDE + DOCS], API-09 [SLIDE].

## C3 — Justificativa acadêmica

Não dá para afirmar que o professor exige Axios, TanStack Query ou cookie HMAC. Não há PDF disponível nesta bancada e, portanto, não conferi slides. O que se pode dizer com precisão é que a referência da skill registra:

- **Axios:** DEC-01 é uma decisão do grupo de usar `fetch` nativo; a seção também registra que Axios foi ensinado como alternativa. A referência menciona conteúdo de slides, mas isso não prova exigência de Axios.
- **TanStack Query:** DEC-02 é decisão do grupo de não usar biblioteca de cache cliente porque não há busca cliente. A referência menciona que o slide apresenta TanStack Query como opção que exige Provider; não estabelece obrigação.
- **Cookie HMAC:** AUTH-03 registra uma decisão do grupo de assinar o cookie com `node:crypto`, sem biblioteca extra, e cita documentação Next.js sobre segredo. Isso tampouco demonstra exigência do professor.
- **Dependências:** STACK-06 registra lista fechada definida pelo grupo; dependências fora dela requerem uma nova decisão explícita.

Decisão prática: não instalar Axios nem TanStack Query com base nessa afirmação. Seguir `fetch` e a arquitetura atual do grupo; manter a assinatura HMAC descrita em AUTH-03 sem acrescentar biblioteca. Se o colega trouxer o PDF, conferir a passagem e distinguir recomendação de requisito antes de atribuir qualquer regra ao professor.
